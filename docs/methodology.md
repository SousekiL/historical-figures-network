# 方法论（Methodology）

本文说明数据管线、口径与已知局限，保证数据可复现、可追溯。

## 1. 数据源

- **CBDB**（中国历代人物传记资料库），SQLite 数据库 `cbdb202409.db`（2024-09 版）。
- 主要用表：`BIOG_MAIN`（人物主表）、`ASSOC_DATA`（社会关系）、`ASSOC_CODES` + `ASSOC_CODE_TYPE_REL` + `ASSOC_TYPES`（关系类型）、`ALTNAME_DATA`（字 / 号）、`TEXT_CODES`（史料出处）、`DYNASTIES`（朝代）。

## 2. 人物范围（不设知名度准入规则）

纳入**所有「有 ≥1 条可考社会关系」的人物**——即 CBDB `ASSOC_DATA` 中作为主体（`c_personid`）或客体（`c_assoc_id`）出现过、且朝代在本项目范围内的人物。共 **40,263 人**、**72,925 条关系**。

- 不按知名度 / 度数做 top-K 筛选；任何人只要留下可考社会关系记录即入选。
- 剔除：孤立点（其所有关联对象均不在范围内）、朝鲜半岛政权（高麗 / 新羅 / 朝鮮 / 韓國）、近现代（中華民國 / 中華人民共和國）。
- 关系范围仅 `ASSOC_DATA`（社会关系）；`KIN_DATA`（亲属关系）不纳入——亲属数据多为族谱自动生成，混入会把「名人社会关系」稀释成家谱。

### 跨朝代判定

跨朝代人物归入其所属的**每一个**档位：

- **主档位** `dynasty_tier`：`c_dy` 所属档位，用于节点配色。
- **全部档位** `dynasty_tiers`：主档位 + 生卒区间与大朝代年代区间求交叠得到的档位，用于朝代筛选。
- 大朝代年代区间由 `DYNASTIES.c_start/c_end` 聚合（宋=960–1279、元=1234–1367、明=1368–1661、清=1644–1911 …）。
- 年份为 0 或缺失时视为不详（CBDB 以 0 表示年份不详，无公元 0 年）；生卒年缺失时退化为序年，再缺失则仅归主档位。
- 例：趙孟頫（1254–1322，CBDB 主标注元）归入「元」「宋」；宋濂（1310–1381，主标注明）归入「明」「元」。

## 4. 关系提取与去重

- 仅保留两端都在入选集合内的关系（保证网络连通、边有意义）。
- CBDB 中每条社交关系双向各存一条（ego / alter），构建时按 `(min(person1, person2), 简化关系类型)` 去重，边无方向。
- 每条关系保留史料出处 `source_text`（书名）与 `source_pages`（页码），在 JSON 中经字符串表压缩（`text_id` → `metadata.texts`）。

## 5. 关系类型映射

`ASSOC_DATA.c_assoc_code` → `ASSOC_CODE_TYPE_REL` → `ASSOC_TYPES` 得到层次化类型，再映射为 7 类简化关系（`type` 字段）：

| 简化类型 | 来源（`ASSOC_TYPES`） | 说明 |
|----------|------------------------|------|
| 師生 | 0202 | 师生 / 问学 |
| 好友 | 0301 | 朋友关系 |
| 家族 | 0901（仅 ASSOC_DATA） | 家庭关系（不含 KIN_DATA） |
| 同僚 | 0402–0406 | 官场（平级/上下级）、政治奥援、荐举 |
| 政敵 | 0407 | 政治对抗 |
| 唱和 | 0207、05xx | 文学艺术交往、著述（赠诗、序跋、墓志等） |
| 交往 | 01xx、06xx、08xx、10xx 及未细分 | 一般社会交往、学术、军事、宗教、财务等 |

原始关系描述保留在 `data/processed/relationships.csv` 的 `subtype` 字段（JSON 中为减小体积不重复存储）。

### 关系大类分组（用于前端筛选）

7 类细类在前端聚合为 4 个**大类**，可按大类筛选：

| 大类 | 包含细类 | 含义 |
|------|----------|------|
| 文学交往 | 唱和、師生 | 诗文唱和、问学师承等文学 / 学术往来 |
| 政治关系 | 同僚、政敵 | 官场协作、政治对抗 |
| 私人关系 | 好友、家族 | 朋友、亲属 |
| 一般交往 | 交往 | 其余社会交往（学术、军事、宗教、财务等） |

## 6. 性别与人物类别

- **性别** `gender`：取自 `BIOG_MAIN.c_female`（1=女，0=男）。注意 CBDB 中 0 同时包含性别不详者，故「男」实际含义为「非女 / 不详」。
- **人物类别** `category`：由该人物在入选网络内主要社会关系类型（排除「家族」）映射而来（唱和→文學家、師生→學者、好友→文人、同僚/政敵→政治家、仅亲属→名門士族、其他→文化名人）。为**推断值**，非人工标注。

## 7. 布局

节点坐标 `x` / `y` 由 **igraph DrL** 力导向布局预计算（归一化到 [0,1]），前端直接渲染，不在浏览器内跑力导向模拟（保证 4 万节点规模流畅）。全量图为 1,708 个连通分量，最大连通分量 35,975 人。

## 8. 可追溯性

- 人物：保留 CBDB 人物 ID（`id` 字段）。
- 关系：保留史料出处（`text_id` → `metadata.texts` 书名）与页码 `source_pages`。

## 9. 已知局限

1. **覆盖不均**：CBDB 社会关系在唐 / 宋 / 元 / 明 / 清较丰富，先秦 / 秦汉 / 魏晋南北朝较薄（传世史料少），故早期朝代人数少（春秋战国 9 人、秦汉 40 人）。
2. **「唱和」占比高**：唐宋部分大量关系来自诗文交往类索引（《唐五代人交往詩索引》《宋人傳記資料索引》），故边类型以「唱和」为主。
3. **性别为近似值**：`c_female=0` 含不详者。
4. **类别为推断值**：不构成权威的「职业/身份」标签。
5. **亲属关系未纳入**：`KIN_DATA` 数据量大且多为族谱自动生成，如需可作独立图层另行叠加。
